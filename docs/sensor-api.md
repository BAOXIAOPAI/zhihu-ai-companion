# 看山小盆｜温湿度接口

## 当前进度

ESP32‑S3 已连接 Wi‑Fi，并通过 SHT31 读取温湿度。手机和电脑均已验证可以打开设备的局域网首页 `/`，JSON 接口也已在浏览器中返回真实读数。

## 读取当前温湿度

```http
GET /api/readings/latest
```

成功时返回 HTTP `200`，响应类型为 `application/json`。以下为设备实测响应：

```json
{
  "temperature_c": 24.5,
  "humidity_percent": 45.4
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `temperature_c` | 数字 | 温度，单位 °C |
| `humidity_percent` | 数字 | 相对湿度，单位 %RH。例如 `45.4` 表示 `45.4%` |

固件在传感器读取失败时返回 HTTP `503`，响应为 `{"error":"sensor_unavailable"}`。页面可以显示「暂无传感器数据」，并在下一轮继续请求。当前已验证 `200` 成功响应。

## 前端怎么开始

手机端和电脑端使用同一份接口约定。异地开发时，先用上面的 JSON 模拟成功响应，再模拟一次 `503` 验证暂无数据状态。接入真实接口后，可以每 2 秒请求一次。

请求路径统一使用 `/api/readings/latest`。如果前端和 API 部署在同一域名下，可以直接用这个相对路径。如果分别部署，API 基础地址通过配置提供，并由后端允许前端域名跨域访问。

## 本地联调

让测试设备和 ESP32 连到同一个热点或路由器。IP 以 ESP32 串口打印的 `WiFi connected. IP:` 为准。本次测试地址为 `http://192.168.43.27/api/readings/latest`，可用于同一局域网内的联调。

## 后续接入

- 异地真实数据联调计划采用「ESP32 上报 → 公网后端 → 手机或电脑网页」。公网后端提供相同的 GET 路径、字段、单位和状态码，前端可沿用取数和展示逻辑。设备上报接口待后端方案确定。
- 接入实体屏幕后，屏幕和 API 可以共用 ESP32 的采样结果，前端接口约定继续沿用。
